## 13:03 — Payroll Dispute Filing in Payroll Batch

**Why:** Let HR file disputes (Unpaid Days, Unpaid Overtime, Over Deduction - Undertime, Over Deduction - Late) in the current batch for a day from a previous posted period, computed from the times entered in the dispute — one at a time or via upload.

**Summary:**
- New table `trn_payroll_disputes` (soft deletes; cascades when the batch employee is removed) and `trn_payroll_incomes.remarks` (dispute date shown next to the income line and on the payslip).
- New income types: DUPD (Unpaid Days), DUPO (Unpaid Days OT), DUOT (Unpaid Overtime), DODU (Undertime Refund), DODL (Late Refund) — all taxable.
- `PayrollDisputeService`: recomputes the disputed day from the entered times (not the raw logs), diffs it against the attendance snapshot of the posted batch that paid that day, and creates income lines on Process/Reprocess (non-manual, so reprocess rebuilds without duplicates). Unpaid Days includes OT beyond the shift as a separate DUPO line (the dispute counts as the OT filing).
- Rules: work date must be before the current period and already paid in a posted batch; batch must be Pending/Processed; same employee + date + type cannot be filed twice (any batch); Unpaid Days with OT blocks Unpaid Overtime for the same day and vice versa. No approval step.
- Batch employee detail → new **Disputes** tab: list (work date, type, filed times, Expected Pay, paid in this batch, "changed after filing"), File Dispute / Edit / View modals, soft delete. All CRUD writes `sys_logs`.
- Form auto-fills from logs + shift once Work Date and Dispute Type are picked, shows what was previously paid, live **Expected Pay** with breakdown, and disables Save when a dispute was already filed.
- New upload type **Disputes** (transaction type 8): UPD/UOT/ODU/ODL codes, blank times auto-fill, per-row validation (open batch on the selected period, duplicates in file and in DB), preview shows expected pay; commit creates disputes linked to the upload.
- Tests: `PayrollDisputeTest` (7 tests: each category amount, UPD+OT two lines, reprocess/zero, HTTP prefill/preview/store/update/duplicate/soft delete, UPD-OT vs UOT block, date/locked batch validation, upload). `npm run build` done; browser smoke test on dev batch #0008 passed (smoke dispute soft-deleted afterwards).

**Summary:**
- New `time_in` / `time_out` columns (string 5, nullable) on `trn_payroll_deductions` and `raw_payroll_deductions`.
- LTDE: Reference Date (work date) + **Time In only** are required; UTDE: Reference Date + **Time Out only**. The other time field is hidden and not saved.
- Hours auto-fill from the time against the employee's shift (same late/undertime policy rules as payroll, grace period included); Hours stays editable.
- Employee Amount = hours × hourly rate (readonly in the form, recomputed server-side); Employer Share = 0; days = 1.
- New JSON preview endpoint `payroll.transaction.employees.deductions.attendance-preview`; the hint shows the shift, minutes, hourly rate, and amount.
- Deductions upload: new template columns `time_in`, `time_out`. LTDE/UTDE rows require reference date + the matching time; hours and amount are computed on upload (typed amounts are ignored).
- The time is stored on the deduction line only — raw biometric logs are not changed.
- Manual deductions list and upload detail now show the reference date with In/Out time.
- Tests: 4 new feature tests; full suite only has the 4 pre-existing unrelated failures. `npm run build` done; browser smoke on batch 0008 passed (test line soft-deleted).
